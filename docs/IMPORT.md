# 数据导入指南

本页对应 V2 2.0.0 的实际导入实现。软件提供的是**表格读取、预设列名匹配、手动字段映射与校验**，没有用 AI 推测任意列的含义。

## 1. 支持什么文件

| 你的目的 | 文件 | 软件入口 |
| --- | --- | --- |
| 批量录入岗位或企业招聘方向 | CSV（`.csv`）、Excel（`.xlsx`、`.xls`） | 岗位页面工具栏“导入” |
| 将原来使用本软件的整套数据迁移过来 | 本软件“另存完整备份”生成的完整 JSON | 数据与备份 → 备份与恢复 → 从外部完整 JSON 恢复 |
| 仅有任意 JSON、PDF、Word 或图片 | 不属于岗位表导入格式 | 先整理成 CSV 或 Excel；不要更改扩展名冒充格式 |

岗位表导入不恢复申请阶段、历史记录、回收站或其他整库信息。表格里即使带有“已投递”“申请阶段”等列，也不会据此创建或覆盖真实申请。

## 2. Excel / CSV 应该长什么样

第一行放表头，第二行起每行对应一个岗位或招聘方向：

| 公司名称 | 岗位名称 | 工作地点 | 投递优先级 | 真实投递入口 | 备注 |
| --- | --- | --- | --- | --- | --- |
| 合成示例企业甲 | 合成需求分析岗位 | 杭州 | A | https://example.com/jobs/demo-a | 虚构示例，不是真实招聘 |
| 合成示例企业乙 | 合成系统实施岗位 | 南京 | B | https://example.com/jobs/demo-b | 虚构示例，不是真实招聘 |

- 必填的是**公司名称、岗位名称、完整工作地点**三个逻辑字段，而不是必须使用完全一致的中文表头。
- 一张表不需要事先创建几十个空列。只放需要的字段即可。
- 不要在表头之前增加大标题、说明行；避免合并单元格、空白表头和重复列名。
- Excel 可以包含多个工作表；软件会先选一个非空工作表，可在导入向导中切换，不会自动合并所有工作表。
- CSV 使用逗号分隔、UTF-8 编码。Excel 另存时选择“CSV UTF-8（逗号分隔）”；含逗号或换行的单元格应由表格软件正确加引号。
- 单文件上限 20MB；数据不超过 10,000 行、100 列。大表请拆分。

可下载：[最简三列示例](../examples/jobs-minimal.csv) · [自定义列名示例](../examples/jobs-custom-headers.csv)。两个文件仅含合成数据。

## 3. “企业名称”能不能导入

**可以，但在当前版本中需要手动映射。**

假设你的文件表头是：

```csv
企业名称,职位,城市,网申网址
合成示例企业甲,合成需求分析岗位,杭州,https://example.com/jobs/demo-a
```

选择文件后，在“预览与映射”步骤中调整：

| 文件原列名 | 软件中的目标字段 |
| --- | --- |
| 企业名称 | 公司名称 |
| 职位 | 岗位名称 |
| 城市 | 完整工作地点 |
| 网申网址 | 真实投递入口 |

这样可以保留原表头，完成导入；也可以提前把表头改为 `公司名称,岗位名称,工作地点,真实投递入口`，让软件初始自动匹配。

自动匹配按预设列名进行，不做模糊语义判断。`企业名称` 和 `企业` 是两个不同的表头；英文也不要随意改大小写。列名前后的空格、单元格内换行可能导致初始匹配失败，此时手动选择目标字段即可。

### 常见自动识别名称

| 软件字段 | 可以初始自动匹配的常见表头 | 需要手动映射的例子 |
| --- | --- | --- |
| 公司名称 | 公司名称、公司、企业、company_name | 企业名称、单位名称 |
| 岗位名称 | 岗位名称、职位名称、建议关注岗位或方向、job_title | 职位、岗位、应聘岗位 |
| 完整工作地点 | 完整工作地点、工作地点、地点、原表地点判断、location_text | 城市、办公地点 |
| 投递优先级 | 投递优先级、优先级、priority | 重要程度 |
| 真实投递入口 | 真实投递入口、投递链接、原表投递入口、apply_url | 网申网址、招聘网址 |
| 截止时间 | 截止时间、原表截止信息、deadline | 截止日期 |
| 最后核验日期 | 最后核验日期、核验日期、原表更新时间、verified_at | 确认时间 |
| 薪资原口径 | 薪资原口径、薪资、月薪、salary_text | 薪酬说明 |
| 备注 | 备注、核验重点、notes | 补充说明 |

这是常见名称摘录。完整可选目标以导入界面的下拉菜单为准。

## 4. 字段值怎样填写

| 字段 | 是否必填 | 填写方式 |
| --- | --- | --- |
| 公司名称 | 必填 | 非空文本 |
| 岗位名称 | 必填 | 非空文本；导入企业招聘方向时也需要填写方向名称 |
| 完整工作地点 | 必填 | 非空文本，例如“杭州”或“南京市江宁区” |
| 主岗位池 | 可选 | 只支持“杭州”“南京”“滨海新区”“其他强推”；缺失时使用当前导入页面的岗位池 |
| 投递优先级 | 可选 | `S` / `A` / `B` / `C`，缺失默认 `C`；旧值“优先”映射 A、“关注”映射 C 并提示，不代表自动重新评分 |
| 真实投递入口／岗位来源 | 可选 | 有效 HTTP(S) 地址或可识别域名，推荐填完整 `https://...` 链接 |
| 截止时间／发布时间／最后核验日期 | 可选 | 推荐 `2026-11-30`；也支持常见年月日格式和 Excel 日期序列值。不解析“尽快”“招满即止”为具体日期 |
| 月薪下限／月薪上限等数值字段 | 可选 | 纯数字，以元为单位，例如 `12000`；不要写 `12k`、`1.2万` 或带逗号的数值 |
| 薪资原口径 | 可选 | 可保存“12k–16k”“面议”等原文；不自动推算年薪或生成证据等级。证据等级默认 Unknown 时，部分薪资展示会显示待核验 |
| 核验时在招 | 可选 | 是／在招／招聘中／开放／true／1；或否／不在招／停止招聘／已关闭／false／0。留空表示未知，不等于停止招聘 |
| 考虑状态 | 可选 | 使用 `active`（考虑中）或 `deferred`（暂不考虑）；留空不表示覆盖掉已有标记 |
| 匹配分等评分字段 | 可选 | 由用户提供数字，软件不会自动评价人岗匹配 |
| 备注 | 可选 | 普通文本；可写需要核验的条件 |
| 岗位 ID | 可选 | 不填会生成 ID；不了解其作用时可直接省略 |

**“工作地点”不等于“主岗位池”。**例如工作地点为上海，仍可以明确放入“其他强推”；软件不会单凭地点文本替你选择岗位池。当前四个岗位池沿用个人版设计，其他城市可归入“其他强推”。

不能解析的数字会提示并将原值保留到备注；不能解析的日期会保留原值并提示，不会凭空补齐。警告不一定阻止导入，必填缺失、无效岗位池、非法优先级或链接等错误需要先修正。

## 5. 完整操作顺序

1. 打开希望接收数据的岗位页面，点击工具栏“导入”。
2. 选择记录类型：具体岗位，或仍需核实岗位详情的企业招聘方向。两类导入都保留待核验性质，不会自动变成已核实招聘。
3. 选择 CSV / XLSX / XLS 文件；如有需要，切换工作表。
4. 查看前 20 行预览。检查每一列的目标字段；将“企业名称”等自定义列手动映射，不需要的列选择“忽略此列”。
5. 查看数据校验。先修正红色错误，再逐项判断警告；通常需要返回原表修改并重新选择文件。
6. 选择重复处理策略：跳过、覆盖、合并非空字段；也可以针对重复行分别选择。软件按记录 ID 或公司、岗位、地点、链接等组合识别重复，不会仅因公司相同就合并所有岗位。
7. 核对最终条数、当前岗位池和策略，勾选确认后点击“确认备份并导入”。写入前自动备份。

首次练习建议使用合成示例，确认字段映射后再处理自己的资料。导入成功后，在软件中使用“登记”建立投递跟进记录；“登记”不是向企业网站自动投递。

## 6. 常见问题

**我只有一列“企业名称”，为什么说缺少公司名称？**

该列默认未匹配。手动映射为“公司名称”即可；同时检查岗位和地点两个必填字段。

**我的表叫“优先城市”，为什么仍然缺少工作地点？**

“优先城市”会映射到另一可选字段 `location_city`，不能替代必填的 `location_text`。如果这一列就是实际工作地点，请手动改为“完整工作地点”。

**为什么表里的“已投递”没有导入？**

岗位导入只更新招聘信息。投递进度请在软件中登记维护；已有整库记录用本软件生成的完整 JSON 备份恢复。

**导出的 JSON 能直接用于完整恢复吗？**

请使用“数据与备份”中的“另存完整备份”。按选中范围导出的岗位 JSON 或第三方任意 JSON，不等于完整备份。

**文件里有未识别的列怎么办？**

能对应软件现有字段就手动映射；没有合适目标的列可以忽略，或把相关内容整理到备注。不能把任意新列导入成一个新的可编辑业务字段。

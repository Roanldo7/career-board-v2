# 主要功能图解

本页复用已有 V2 隔离验证截图，全部使用合成企业、岗位、投递和备注，不含作者的真实求职资料。部分截图来自 V2 验证阶段，少量标题文案与最终成品不同。截图中的数据不会随 EXE 自动导入。

## 1. 先整理岗位，再跟进申请

![合成岗位工作台](images/overview.png)

侧栏分别进入四个岗位池和“投递进度”。岗位列表用来整理机会，投递进度用来跟进实际申请；两者有关联，但不是同一条记录。

- “新增岗位”适合逐条录入；批量表格使用“导入”。
- 表格与看板视图可以切换；当前工作台可搜索、筛选、分组和排序。
- 绿色标识已登记的机会；暂不考虑标记可与已登记重叠，界面优先显示暂不考虑的提示色。
- 机会记录不等于企业仍在招聘，日期、入口和开放状态需要自己核实。

## 2. 在同一数据范围内筛选和阅读

![银行筛选：合成示例](images/bank-filter.png)

搜索、筛选、分组与排序可以组合使用；银行按钮切换相关范围。列表条数、选择和导出依赖当前操作范围，不能把筛选后的空列表理解为原始数据被删除。

页面、部分查询和阅读位置可以保留，适合在不同岗位池之间切换后继续查看。需要回到默认范围时使用“重置”。

## 3. 多选、登记与暂不考虑

![跨页多选与右键菜单](images/batch-actions.png)

勾选记录后可右键操作：

- **登记**：建立或关联软件内的投递跟进记录。它不会打开招聘网站并自动提交简历。
- **暂不考虑／恢复考虑**：保留机会信息，同时记录当前个人取舍；这与删除不同。
- **删除**：进入回收站流程，后续恢复或永久删除需要分别判断。

同一企业的不同岗位可以有独立申请。不要仅因公司相同就假定所有岗位都已投递。申请状态、后续动作和日期在“投递进度”中维护；无需通过重新导入岗位表来更新面试阶段。

## 4. 备份、清单导出与恢复各有用途

![人工备份与完整恢复](images/backup-restore.png)

| 操作 | 适合用途 |
| --- | --- |
| 岗位／申请清单导出 | 整理选中或指定范围的信息，供表格查看 |
| 创建人工备份 | 在重要修改前保存一个完整业务数据时点 |
| 另存完整备份 | 将完整业务数据保存到自己选择的位置，便于换电脑迁移 |
| 从外部完整 JSON 恢复 | 从本软件生成的完整备份恢复，先预览、确认，再替换整库 |

人工备份独立保留；自动备份保留最近 10 份。恢复会回到备份时点，不会自动合并备份之后新增的修改。操作前请认真检查预览和保护提示。

业务数据位于本机 `%APPDATA%\CareerBoardV2`，与 EXE 分离。关闭前可以使用“保存并退出”。GitHub 仓库和 Release 不承担自动同步你个人数据的功能。

## 5. 导入从字段映射开始

“企业名称”这样的自定义表头可以手动映射为“公司名称”；不要求事先改成统一模板，也不代表软件会语义理解所有列名。文件形式、最低字段要求、自动识别名称和详细操作见 [数据导入指南](IMPORT.md)。

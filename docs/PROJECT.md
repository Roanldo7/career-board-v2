# 项目介绍与版本记录

## 解决的问题

个人秋招需要同时处理岗位发现、企业筛选、投递登记、测评与面试跟进。原先分别维护的网页链接、Excel 和笔记容易造成状态重复填写、待办遗漏，以及“岗位线索”与“实际申请”混淆。

本项目将企业、岗位、线索和申请记录作为不同对象管理，通过本地桌面界面完成录入、筛选、登记、状态更新和备份。产品目标是减轻作者自己的信息整理与过程跟进负担。

## 已采用的设计

- 业务数据与 EXE 分离，更换程序时不要求重新导入或重置个人数据库。
- 岗位表格导入与完整备份恢复分开；恢复前展示预览并确认。
- 使用事务命令更新记录，保留修订检查、备份与恢复处理，减少整库覆盖引入的数据风险。
- 开发预览必须指定独立 profile，避免开发试用直接写入正式数据。
- 偏好状态与业务信息分别管理，支持连续使用时恢复页面和阅读设置。

## 作者与 AI 的协作

作者提出需求与验收标准，决定功能优先级、交互取舍，并通过实际使用反馈迭代。Codex 根据这些要求协助实现代码、排查问题、执行验证和制作 Windows 成品。本文不以代码量或 AI 生成量代替作者的业务贡献，也不虚构节省时间、用户规模或成功率。
